## 4. USB (после joy-образа)
- Bring-up образ: DWC3 dual-role выбрал peripheral, хоста не было.
- **Joy-образ**: DTS `dr_mode=host`, `CONFIG_USB_DWC3_HOST=y` —
  PHY `mode=host`, xHCI поднял шины **usb1/usb2**, в
  `/sys/bus/usb/devices` есть `usb1`, `usb2`, `1-0:1.0`, `2-0:1.0`.
  Значит Type-C умеет host; осталось проверить powered hub и стики.
- RAM в joy-образе: **87.2 МБ** (`CMA 32M`), pi4joy запущен на `:8090`.
- Подключён питаемый хаб: `05e3:0610` GenesysLogic **USB2.1 Hub**,
  4 порта (`1-1-port1..4`), виден как `1-1`; host работает.
- LAN: `eth0` link **100Mbps/Full**, ping НСУ `192.168.127.250` — OK;
  pi4joy установил TCP к НСУ (`192.168.127.1:.. -> 192.168.127.250:80`).
- Джойстик напрямую в Type-C: **Radiomaster TX12 Joystick**
  (`1209:4f54`, OpenTX), HID Gamepad, `/dev/input/by-path/...-event-joystick`;
  pi4joy `/healthz` → `online:1`.
- НСУ `/api/v1/joysticks` показывает `remote-pi4joy-1` (`Online=true`,
  `AssignedDroneID=1`); RC-каналы идут.
- Через хаб джойстик не определялся — нужен data-порт/кабель;
  напрямую работает.
- При повторном подключении через разветвитель TX12 снова онлайн, но в
  dmesg были `usb1-port1 reset rc=-11` и `descriptor read/64, error -71`:
  питание/кабель на пределе, лучше powered hub с нормальным 5 В.
- **Питание:** Type-C в host-режиме не выдаёт VBUS (`vbus_en=0`).
  Без разветвителя/хаба с питанием плата и джойстик обесточены:
  data-кабель сам по себе не питает. Разветвитель «data + 5 В» —
  это и есть питание платы и стика.
- **Долгое исчезновение:** pi4joy держит offline-слот
  `offlineRetentionScans=6000` при скане 100 мс = **10 минут**, чтобы
  не менять привязку слота. Можно уменьшить при необходимости.

## 8. Вывод для Pi4Joy
1. Включить USB host (DTS + kernel) — без этого джойстики не появятся.
2. Пропатчить pi4joy под 32-бит (`input_event` 16 байт) — сделано,
   бинарник `firmware/pi4joy/opt/pi4joy/pi4joy` (ELF ARM).
3. Включить eudev/by-path (или патч сканера).
4. Собрать `lcpi_joy`, прошить, проверить хаб и стики.
