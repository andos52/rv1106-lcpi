# 15. Радио-прошивка дрона (`lcpi_radio`)

## 1. Цель
Полевой узел дрона на LCPI-RV1106 V1.4: камера SC3336 → H.265 → `vcpd`
(`transport=radiod`) → `radiod`/ULAMA → USB **AR9271** → НСУ.
LTE/WireGuard не используются; обратного видео нет.

## 2. Состав и профиль
- База: masha **v1.8.0** (`~/rv1106-sdk/bort4g-radio`).
- `BoardConfig-SPI_NAND-...LCPI_RV1106-IPC.mk`: SPI NAND, CMA 32M,
  `RK_APP_TYPE=`, `ROCKCHIP_TEST=n`, вендорный Wi-Fi off.
- DTS `rv1106g-lcpi-rv1106.dts`: `dr_mode="host"` (нужен и AR9271, и USB).
- Kernel: USB host/DWC3 + `ath9k_htc`/`ath9ku`, `mac80211`, `cfg80211`.
- Rootfs: `radiod`, `ctrld`, `vcpd`, `ushd`, `S39wifi`, `S96radiod`.
- `vcpd`: `transport=radiod`, source `/dev/video0`, node 1, dst 254,
  320×240@30, 128 кбит/с, GOP 6.
- IP борта: `.1` (`node_id=1`); станция: AR9271 channel 6.

## 3. Сборка
```bash
SDK_DIR=$HOME/rv1106-sdk/bort4g-radio ./scripts/build_radio.sh
# перепаковка без allsave:
SDK_DIR=$HOME/rv1106-sdk/bort4g-radio ./scripts/build_radio.sh --repack-only
```
Результат: `dist/lcpi-radio.img` + `.sha256`.

`build_radio.sh` перед сборкой восстанавливает `S96radiod`/`S99unow`
(после joy-сборки) и ставит `node_id=1`, затем удаляет pi4joy-файлы
из rootfs и перепаковывает образ.

## 4. Что проверить после прошивки
1. UART 115200: загрузка, разделы NAND.
2. USB: AR9271 виден в `/sys/bus/usb/devices` (`0cf3:9271`).
3. `S39wifi status` → `mon0` monitor, channel 6 (2437).
4. `lsmod` → `ath9k_htc`/`ath9ku`, `mac80211`, `cfg80211`.
5. `S96radiod status` → radiod/ctrld/vcpd запущены.
6. Камера: `ls /dev/video*`, `dmesg | grep -i sc3336`.
7. `vcpd` source совпадает с реальным video-узлом.
8. НСУ: radiod/ulama-gw, видео в UI, UVCP READY/STOP.

## 5. Трудности и риски
| Риск | Влияние | Что делать |
|---|---|---|
| Type-C не выдаёт VBUS | AR9271/камера не питаются | powered hub/OTG + внешнее 5 В; проверить `vbus_en` |
| AR9271 не тот чип | нет `mon0` | только AR9271 (`0cf3:9271`), firmware htc_9271 |
| Камера не определилась | нет `/dev/video*` | FPC/питание/драйвер SC3336, проверить DTS/rkaiq |
| Другой video-узел | vcpd читает пустоту | поправить `source=` в `/etc/vcpd.conf` |
| Несовместимость со станцией | нет видео/UVCP | channel 6, node id, v1.8 ULAMA vs masha-gcs |
| 128 МБ RAM / CMA | OOM, пропуски кадров | CMA 32M, минимальный профиль, замер RSS |
| USB reset/descriptor errors | задержки/отвалы | качественный БП/хаб, короткий кабель |
| node `.1` занят | конфликт IP | согласовать node id и routes на НСУ |
| Rootfs место | media libs/radiod | следить за `df`, чистить тесты |

## 6. Диагностика
```sh
dmesg | grep -i -E 'usb|ath9k|cfg80211|sc3336|rkisp'
ls /sys/bus/usb/devices; lsusb
iw dev mon0 info
cat /etc/vcpd.conf
cat /var/log/vcpd/vcpd.log
netstat -tn
```
На НСУ: `journalctl -u radiod -u ulama-gw`, `systemctl status radiod ulama-gw`,
проверить `routes.conf`/`radio-wifi.env`.
