# 16. Сравнение LCPI-RV1106 V1.4 и Luckfox Pico Ultra

Сравнение с платой, которую заменяем: **LuckFox Pico Ultra** (профиль
`BoardConfig-EMMC-...Luckfox_Pico_Ultra-IPC.mk`, payload `bort4g`/masha).
Обе — RV1106, но это **не взаимозаменяемые платы**.

## 1. Спецификации
| Параметр | LCPI-RV1106 V1.4 | Luckfox Pico Ultra |
|---|---|---|
| SoC | RV1106**G2** | RV1106**G3** |
| CPU/NPU/VPU | Cortex-A7 + RISC-V, 0.5 TOPS, H.264/H.265 | то же |
| RAM | **128 МБ** DDR (в корпусе) | **256 МБ** DDR (в корпусе) |
| Постоянная память | **256 МБ SPI NAND** (W25N02KV) | **8 ГБ eMMC** (профиль: rootfs 6 ГБ) |
| Разделы | env 256K, idblock 256K, uboot 512K, boot 4M, oem 30M, userdata 10M, rootfs 210M | env 32K, idblock 512K, uboot 256K, boot 32M, oem 512M, userdata 256M, rootfs 6G |
| CMA | 32 МБ (снижено с 66 МБ) | 66 МБ |
| Ethernet | 100 Мбит (HR911105A) | 100 Мбит |
| Камера | 1 × MIPI CSI, SC3336 3MP | MIPI CAM1 + USB CAM2 (по `bort4g`) |
| USB | 1 × Type-C, host/device; **VBUS не выдаёт** | USB host для модема/LTE в payload |
| microSD | есть | — (не полагаемся) |
| GPIO | 2×20 отверстий, **без официальной pinout** | стандартный 40-pin Luckfox |
| Питание | 5 В / 2 А Type-C | 5 В |
| Документация/SDK | своего SDK/схемы нет, SDK Luckfox как база | официальный SDK/профиль |
| Габариты | 30 × 68.5 мм, 26 г | — |

## 2. Чем LCPI хуже
1. **Вдвое меньше RAM:** 128 против 256 МБ. При CMA 32 МБ Linux получает
   ~87 МБ (у Ultra ~180 МБ).
2. **В 32 раза меньше flash:** 256 МБ NAND против 8 ГБ eMMC; rootfs всего
   210 МБ, userdata 10 МБ.
3. **SPI NAND медленнее и изнашивается:** нет eMMC, нет A/B, запись логов
   и обновлений ограничена.
4. **Один USB Type-C без VBUS:** AR9271/джойстики требуют powered hub или
   OTG с питанием; на Ultra USB-host для модема уже был в payload.
5. **Одна камера:** MIPI SC3336; USB-камера возможна только через хаб и
   при наличии питания/памяти. У Ultra в payload было две камеры.
6. **Нет официальной pinout/схемы:** 2×20 без подписей; UART/GPIO
   приходится искать прозвонкой.
7. **Нет готового образа/SDK под плату:** профиль, DTS, разделы и драйверы
   собраны самостоятельно; риск неверной периферии выше.
8. **Меньше запаса по сервисам:** тяжёлый Python-payload `bort4g`
   (camd, boardctld, linkstatus, WG) сюда не помещается вместе с камерой.

## 3. Что из этого вытекает
- **Нельзя один-в-один перенести payload Pico Ultra.** Для LCPI нужен
  облегчённый стек: радио v1.8 (C: radiod/vcpd/ctrld) или Pi4Joy (Go),
  без camd/boardctld/linkstatus и без второй камеры.
- **Видео — только облегчённый профиль:** 320×240@30, 128 кбит/с, один
  поток; 720p/высокий битрейт и dual-camera рискованны по RAM.
- **Нет места под записи/логи/обновления:** логи в tmpfs, userdata 10 МБ;
  обновление — полной перепрошивкой, без A/B.
- **USB-питание становится частью архитектуры:** powered hub/OTG,
  внешние 5 В, контроль просадки; ошибки `-110/-32` — признак предела.
- **Сборка и восстановление только свои:** Maskrom/`upgrade_tool`, образ
  `update.img`, без eMMC-разделов и штатного SD-обновления Ultra.
- **GPIO/UART без схемы:** сначала прозвонка/поиск UART, потом периферия.

## 4. Ограничения по подсистемам
| Подсистема | Ограничение LCPI | Следствие |
|---|---|---|
| RAM | 128 МБ, CMA 32M | один видеопоток, минимум сервисов, риск OOM |
| Flash | 256 МБ NAND | rootfs 210M/oem 30M/userdata 10M; нет A/B и хранения видео |
| NAND | износ/скорость | логи только tmpfs, редкая запись, аккуратные обновления |
| USB | один Type-C, нет VBUS | hub/OTG + внешнее питание, один стек на шину |
| Камера | один MIPI | нет второй/USB-камеры без хаба и запаса RAM |
| Сеть | 100M Ethernet | достаточно для видео/управления, но без запаса |
| GPIO | неизвестная pinout | UART/GPIO только после проверки |
| Софт | нет вендорского SDK | свои DTS/профили, выше риск bring-up |

## 5. Что компенсирует
- CMA 32 МБ, минимальный rootfs, отключение тестов/лишних пакетов,
  отдельные образы `lcpi_joy` и `lcpi_radio` (не совмещать).
- `vcpd` 320×240@30/128 кбит/с, один поток, без записи на NAND.
- Логи в tmpfs, `log-persist` только в 10 МБ userdata, ротация.
- Powered hub 5 В ≥2.5 А, короткий кабель, замер напряжения под нагрузкой.
- Ethernet для Pi4Joy/НСУ; AR9271 только на радио-образе.
- Хранить `lcpi-joy.img`/`lcpi-radio.img` и SHA256 для отката через Maskrom.
- microSD использовать как аварийный носитель/данные, если понадобится.

## 6. Вывод
LCPI-RV1106 подходит как **более дешёвый и компактный узел** для Pi4Joy и
радио-камеры с облегчённым профилем. Как замена Pico Ultra «один-в-один»
она **хуже**: половина RAM, в 32 раза меньше flash, медленный NAND, один
USB без питания и одна камера. Полный payload `bort4g` (LTE/WG + camd +
две камеры) на неё переносить не стоит; для неё нужны отдельные
`lcpi_joy` и `lcpi_radio` с урезанным набором сервисов.
