# 05. Требования к прошивке (радио-режим masha)

## 1. Назначение
Полевой узел masha на LCPI-RV1106 V1.4: захват камеры, аппаратное H.265,
передача видео на НСУ (`masha-gcs`) по радио через USB **AR9271**.
Приём видео на борт не требуется; вниз идут только управление и телеметрия.

LTE-модем и WireGuard не используются.

## 2. Функциональные требования
| ID | Требование |
|---|---|
| FR-1 | Образ собирается из masha v1.8.0 под профиль LCPI без ручной правки SDK. |
| FR-2 | Параметры задаются конфигом: node id, радио-канал, источник/профиль камеры, битрейт, GOP/IDR, MTU, FEC. |
| FR-3 | Прошивка через USB Maskrom (`upgrade_tool`/SocToolKit) или microSD. |
| FR-4 | Загрузка: `S39wifi` поднимает AR9271 (`ath9k_htc`/`ath9ku`), создаёт `mon0` в monitor на канале 6 (2437 МГц). |
| FR-5 | `S96radiod` запускает `radiod` → `ctrld` → `vcpd` → `ushd`; `vcpd` кодирует H.265 и шлёт ULAMA VIDEO через `radiod`. |
| FR-6 | UVCP по радио: `READY`/`STOP`/`PING`; `vcpd` отвечает `PONG` и держит lease; `always_on` сохраняет стек камеры тёплым. |
| FR-7 | Видео идёт только вверх; обратного видеопотока нет. |
| FR-8 | Watchdog: восстановление USB-стика, `mon0`, `radiod`, `vcpd`; логи в tmpfs + persist в `/userdata/log`. |
| FR-9 | Восстановление платы повторной прошивкой через Maskrom/SD. |

## 3. Нефункциональные требования
| Параметр | Требование |
|---|---|
| RAM | 128 МБ; CMA 32 МБ; без swap |
| Flash | 256 МБ SPI NAND: rootfs 210 МБ, oem 30 МБ, userdata 10 МБ |
| Видео (по умолчанию v1.8.0) | 320×240, 30 fps, 128 кбит/с, H.265, GOP 6, IDR 2000 мс |
| Радио | AR9271, monitor, канал 6, `frag_mtu=1440`, `tx_pacing=400` |
| Задержка | определяется эфиром и GOP; первый кадр ≤ 10 с после READY |
| Стабильность | 30 мин без отвалов USB/радио |
| Питание | 5 В / 2 А Type-C + питание USB-стика (hub/OTG) |

## 4. Конфигурируемые параметры
| Ключ | Значение по умолчанию | Смысл |
|---|---|---|
| `node.id` | `1` | ULAMA node id (1..253) |
| `radiod.iface` | `mon0` | monitor-интерфейс |
| `radiod.channel` | `2437` (ch6) | частота |
| `radiod.tx_rate_mbps` | `6` | legacy TX rate |
| `radiod.tx_slot_size` | `2` | пакетов в TX-слоте |
| `radiod.ack_timeout_us` | `60000` | ACK timeout |
| `radiod.ack_max_retry` | `2` | повторы |
| `vcpd.source` | `/dev/video0` | устройство камеры (проверить) |
| `vcpd.width/height/fps` | `320/240/30` | профиль |
| `vcpd.bitrate` | `128` | кбит/с |
| `vcpd.gop` | `6` | GOP |
| `vcpd.idr_interval_ms` | `2000` | принудительный IDR |
| `vcpd.frag_mtu` | `1440` | байт на фрагмент |
| `vcpd.kf_extra_copies` | `0.5` | доп. копии ключевых |

| `vcpd.fec` | `true` | XOR-FEC ключевых |

## 5. Совместимость адаптера
- В образе v1.8.0 — **AR9271** (`0cf3:9271`) через `ath9k_htc`/`ath9ku`.
- MW300UH (RTL8192EU) этим образом не поддерживается; для него нужен
  отдельный monitor/injection-драйвер и проверка.
- USB-стик требует host-режима и достаточного питания.

## 6. Критерии приёмки
- Плата грузится, разделы NAND монтируются.
- `S39wifi status` → `mon0` monitor ch6; `lsmod` содержит radio-модули.
- `S96radiod status` → radiod/ctrld/vcpd запущены.
- На НСУ в UI идёт видео борта; пропадание и возврат стика восстанавливаются.
- После `reboot` радио и видео возвращаются без ручных команд.

## 7. Ограничения и неизвестные
- Не подтверждён video-узел камеры (`/dev/video0` vs `/dev/video14`).
- Не проверены USB-host/питание стика на Type-C.
- 128 МБ RAM: возможен дефицит при тяжёлом профиле; CMA уже снижен до 32 МБ.
- Нет схемы LC Tech; DTS собран из Pro Max и требует проверки на железе.
